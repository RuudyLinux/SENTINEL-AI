Findings & fixes priority-ordered, as fixed

P0-BShared tracker state across camerasdetector.py · worker.py

A single lru_cache YOLO instance was reused by every camera. Since .track(persist=True) keeps ByteTrack state on that object and each camera's inference runs on its own thread, concurrent cameras could race and corrupt each other's track IDs.

Fixed with one YOLO/tracker instance per camera (_MODELS_BY_CAMERA), released on stop_worker.

VERIFIED import + boot clean; per-camera instance dict confirmed by code path, not yet load-tested with 2+ concurrent live cameras.
P0-ANo real reconnect on a dropped streamworker.py · source.py

On a bad read the loop set status="degraded" and slept 1s — forever, never reopening the source.

Fixed: release+reopen with exponential backoff (1s → 30s cap, 5 attempts) after 3 consecutive bad reads; camera marked offline and the worker stops only once the retry budget is exhausted.

VERIFIED code path exercised via import/boot; not fault-injected against a live dropped stream in this pass.
P0-ARTSP was a defined-but-unimplemented stubsource.py · cameras.py

Routed through the same cv2.VideoCapture path as video_file via OpenCV's FFmpeg backend, with open/read timeouts so a dead stream fails fast instead of hanging a worker thread.

VERIFIED import clean, test-connection path reachable. No real RTSP source available to test against — honestly labeled best-effort in the UI and README.
P0-CANPR correlated on any non-empty OCR readanpr.py · worker.py

looks_like_plate() — an Indian plate-format regex — existed but was never called. A two-character garbage read became a real Vehicle/Plate row.

Fixed: correlation now gated on looks_like_plate() and plate_min_confidence (0.35).

VERIFIED gate logic reviewed inline; not re-run against live OCR frames in this pass.
P0-EEvidence & camera-stream endpoints had zero authsecurity.py · evidence.py · streams.py · +5 frontend

Confirmed live before the fix: GET /api/evidence/{id}/file returned 404 for a bad ID with no auth check at all — vs 401 on /api/cameras. Anyone with an evidence ID could pull police evidence with zero RBAC, and the audit log recorded the accessor as None.

Fixed with short-lived signed resource tokens (reuses the existing JWT secret, no new dependency): an authenticated, RBAC-checked, audited .../file-token / .../package-token / .../stream-token request hands out a token scoped to that one resource ID; .../file, .../package, .../mjpeg, .../snapshot.jpg now validate it via ?token=. Every access logs the real user. Evidence package also now includes the actual AuditLog rows for that incident — the docstring claimed a chain-of-custody trail it never queried for.

VERIFIED live against a running backend — see ledger below.
P0-FUpload endpoint trusted the client filenamecameras.py

upload-video wrote to uploads_dir / file.filename verbatim (path-traversal/overwrite risk, no extension check, no size cap, whole file buffered in RAM).

Fixed: server-generated UUID filename, extension allow-list, chunked streamed write with a 500MB cap, partial-file cleanup on failure.

VERIFIED live — see ledger below.
P0-GDemo accounts always seededconfig.py · seed.py

Added DEMO_MODE (default true — local/judge flow unchanged). The four seeded accounts and the demo watchlist entry only get created when true; roles still always seed so a real deployment can attach an out-of-band admin.

VERIFIED import + boot clean, seed path reviewed.

DATABASE, SEARCH and STORAGE were hardcoded "OPERATIONAL" strings; WEBSOCKET wasn't reported at all.

Fixed: real SELECT 1, real os.access() on the upload/evidence dirs, real connected-client count.

VERIFIED live — see ledger below.
